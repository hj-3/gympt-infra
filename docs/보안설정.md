### VPC 격리

**서브넷 분리**:
```
Public Subnet (인터넷 접근)
└── ALB, NAT Gateway만 배치

Private Subnet (NAT Gateway 경유)
└── EKS Nodes, Lambda 함수

Database Subnet (완전 격리)
└── RDS, ElastiCache (인터넷 접근 불가)
```

**보안 그룹 구성**:

```hcl
# ALB Security Group
resource "aws_security_group" "alb" {
  name        = "gympt-${var.environment}-alb-sg"
  vpc_id      = aws_vpc.main.id

  # HTTPS만 허용
  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
    description = "Allow HTTPS from internet"
  }

  # HTTP (CloudFront에서만)
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
    description = "Allow HTTP for redirect"
  }

  # EKS NodePort로만 Egress
  egress {
    from_port       = 30000
    to_port         = 32767
    protocol        = "tcp"
    security_groups = [aws_security_group.eks_nodes.id]
    description     = "Allow traffic to EKS nodes"
  }

  tags = {
    Name = "gympt-${var.environment}-alb-sg"
  }
}

# EKS Node Security Group
resource "aws_security_group" "eks_nodes" {
  name        = "gympt-${var.environment}-eks-nodes-sg"
  vpc_id      = aws_vpc.main.id

  # ALB에서만 접근
  ingress {
    from_port       = 30000
    to_port         = 32767
    protocol        = "tcp"
    security_groups = [aws_security_group.alb.id]
    description     = "Allow NodePort from ALB"
  }

  # 노드 간 통신
  ingress {
    from_port = 0
    to_port   = 65535
    protocol  = "-1"
    self      = true
    description = "Allow inter-node communication"
  }

  # 모든 Egress (VPC Endpoints 접근 포함)
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
    description = "Allow all outbound"
  }

  tags = {
    Name = "gympt-${var.environment}-eks-nodes-sg"
```

## WAF 구성 변경 (2026-05-29)

### 변경 내용

기존 `terraform/modules/waf`(Regional WAF)를 제거하고, WAF를 CloudFront 배포 단계에서 직접 연결하도록 변경했다.

**변경 전**:
```
인터넷 → CloudFront → Regional WAF(ELB/ALB) → ALB → EKS
```

**변경 후**:
```
인터넷 → CloudFront + WAF(CLOUDFRONT scope) → ALB → EKS
```

**이유**:
- CloudFront scope WAF는 글로벌 엣지에서 트래픽을 차단하므로 Regional WAF보다 비용 효율적
- 악성 요청이 리전 내부로 들어오기 전에 차단 가능
- Regional WAF와 CloudFront WAF를 이중으로 운영할 필요 없음

**CloudFront WAF 연결 방법** (AWS Console 또는 Terraform):
```hcl
# CloudFront에 WAF ACL 연결
resource "aws_wafv2_web_acl" "cloudfront" {
  name  = "gympt-prod-cloudfront-acl"
  scope = "CLOUDFRONT"  # us-east-1 리전에서 생성해야 함
  provider = aws.us_east_1

  default_action { allow {} }

  rule {
    name     = "AWSManagedRulesCommonRuleSet"
    priority = 1
    override_action { none {} }
    statement {
      managed_rule_group_statement {
        name        = "AWSManagedRulesCommonRuleSet"
        vendor_name = "AWS"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "CommonRuleSet"
      sampled_requests_enabled   = true
    }
  }

  visibility_config {
    cloudwatch_metrics_enabled = true
    metric_name                = "gympt-prod-cloudfront-acl"
    sampled_requests_enabled   = true
  }
}

# CloudFront에 연결
resource "aws_cloudfront_distribution" "main" {
  # ...
  web_acl_id = aws_wafv2_web_acl.cloudfront.arn
}
```

> **주의**: CloudFront scope WAF는 반드시 `us-east-1` 리전에서 생성해야 한다.

## HashiCorp Boundary — Zero-Trust 접근 제어 (2026-05-29)

### 개요

HashiCorp Boundary를 통해 EKS, RDS 등 내부 리소스에 대한 접근을 중앙 관리한다. SSH/kubectl 등 직접 접근 대신 Boundary 세션을 통해 접근하므로 자격증명 노출 없이 감사 로그와 함께 접근을 제어할 수 있다.

### 아키텍처

```
운영자 로컬
    │
    │ boundary connect (CLI / Desktop)
    ▼
Boundary EC2 (Public Subnet)
├── Controller (9200 API/UI, 9201 Cluster)
├── Worker (9202 Proxy)
└── PostgreSQL 15 (내부)
    │
    │ 세션 터널
    ▼
내부 리소스 (Private Subnet)
├── EKS API (kubectl)
├── RDS PostgreSQL (psql)
└── ElastiCache Redis
```

### Terraform 리소스

생성되는 AWS 리소스:

| 리소스 | 이름 | 설명 |
|--------|------|------|
| EC2 | `gympt-prod-boundary` | Boundary Controller + Worker + PostgreSQL |
| KMS Key | `gympt-prod-boundary-root` | Boundary root seal key |
| KMS Key | `gympt-prod-boundary-worker-auth` | Worker 인증 key |
| KMS Key | `gympt-prod-boundary-recovery` | 복구 key |
| IAM Role | `gympt-prod-boundary-role` | SSM + KMS 접근 |
| Security Group | `gympt-prod-boundary-sg` | 9200/9201/9202 허용 |

### 배포 절차

```bash
# 1. Boundary DB 패스워드 환경변수 설정
export TF_VAR_boundary_db_password="your-secure-password"

# 2. Boundary 모듈만 apply
cd terraform/environments/prod
terraform init
terraform apply -target=module.boundary

# 3. 초기화 로그에서 admin 비밀번호 확인
aws ssm start-session \
  --target $(terraform output -raw boundary_instance_id) \
  --region ap-northeast-2

cat /var/log/boundary-init.log
```

### 운영자 접근 설정

**Boundary CLI 설치**:
```bash
# macOS
brew install hashicorp/tap/boundary

# 접속
export BOUNDARY_ADDR="http://$(terraform output -raw boundary_public_ip):9200"
boundary authenticate password \
  -auth-method-id=<auth_method_id> \
  -login-name=admin
```

**kubectl 터널링 (EKS)**:
```bash
# Boundary를 통해 EKS API 포트 포워딩
boundary connect -target-id=<target_id> -listen-port=6443

# 별도 터미널에서 kubectl 사용
kubectl --server=https://127.0.0.1:6443 get nodes
```

**RDS 접속**:
```bash
boundary connect postgres \
  -target-id=<target_id> \
  -dbname=gympt \
  -username=gymptadmin
```

### 보안 고려사항

1. **`allowed_cidr_blocks`**: 현재 `0.0.0.0/0`으로 설정되어 있음. 운영 VPN/사무실 IP로 제한 필요.
2. **TLS**: 현재 `tls_disable = true`. 프로덕션 운영 시 ALB 또는 Let's Encrypt 인증서로 HTTPS 적용 권장.
3. **admin 패스워드**: 초기화 후 `/var/log/boundary-init.log`의 admin 패스워드를 즉시 변경할 것.
4. **PostgreSQL**: EC2 내부 PostgreSQL은 localhost만 접근 가능하도록 `pg_hba.conf`에서 외부 접근 차단됨.

## IAM 경로 규칙 (2026-05-29)

### Secrets Manager / SSM 경로 형식

External Secrets Operator가 AWS Secrets Manager에서 시크릿을 가져오는 경로 형식:

```
gympt/{env}/{서비스명}
예: gympt/prod/database
    gympt/prod/redis
    gympt/prod/jwt
    gympt/dev/backend-api
```

IAM 정책의 Resource ARN도 이 형식과 일치해야 한다:

```hcl
# terraform/modules/iam/main.tf — external_secrets 정책
Resource = "arn:aws:secretsmanager:${var.aws_region}:*:secret:${var.project_name}/${var.env}/*"
# 결과: arn:aws:secretsmanager:ap-northeast-2:*:secret:gympt/prod/*

Resource = "arn:aws:ssm:${var.aws_region}:*:parameter/${var.project_name}/${var.env}/*"
# 결과: arn:aws:ssm:ap-northeast-2:*:parameter/gympt/prod/*
```

> 이전에 `gympt-prod/*` (하이픈) 형식을 사용했는데, 실제 시크릿 경로(`gympt/prod/...`)와 불일치하여 External Secrets에서 `AccessDeniedException`이 발생했다. 2026-05-29에 수정됨.
